## Summary

Ticket: IR-866 (RT child of IR-210). This is a code review with the `rust-review` lane folded in, over `git diff origin/main...HEAD` of PR 128 (one commit, 559313a, merge base 561691e). The PR replaces 152 `/// Trace:` doc lines on test functions with `#[trace(...)]` from `ix-trace-rs`. It imports the attribute as `use ix_trace_rs::trace;` in each of 21 test modules, and adds `ix-trace-rs` as a dev-dependency of the root crate and the footprint crate, plus an `allow-git` entry in `deny.toml`. One new `Cargo.lock` package resolves from a single source (`git+https://github.com/agent-ix/ix-trace-rs?branch=main#9378a67`, the current `main` of that repository).

Faithfulness was scripted, not sampled. For every tracked `.rs` file, the ordered list of (item, sorted id list) was extracted from the base `/// Trace:` lines and from the head `#[trace]` attributes plus any remaining `/// Trace:` lines. The lists are identical in all 23 files. There are 159 base `Trace:` lines: 152 converted and 7 left. There are 152 `#[trace]` attributes. 334 id occurrences are on both sides, and no id was added, dropped or moved. Every `#[trace]` sits in the attribute block of a `#[test]` function, including the two inside `proptest!` blocks. None is on a helper or production item, and none uses the path-qualified `#[ix_trace_rs::trace]` form, which binds nothing.

## Verdict

**CONDITIONAL, mergeable after fixes**: four low findings, no medium or high in this lane. The PR-blocking item is the spec contradiction in the gap-analysis artifact (SR-12331 FND-001).

What was checked and holds:

- **Faithfulness.** Scripted, per file and per function (see Summary). All 152 attribute id lists equal the deleted doc lines as multisets and in order. Every attribute sits on the `#[test]` fn its doc line described. Prose notes survive, with FND-002 as the one exception: two notes lost their pairing with an id.
- **Imports and feature gating.** Every `#[trace]` file imports `use ix_trace_rs::trace;` at a scope that is compiled whenever the attributed tests are. That is the file top for the `#![cfg(feature = ...)]` files; `mod json` under `#[cfg(feature = "snapshot-json")]` in tests/snapshot.rs; `mod tests` under `#[cfg(test)]` in src/exact/equality.rs; and src/accounting_tests.rs, which is included only under `#[cfg(test)]`. The bare attribute is used, never the path-qualified form, which binds nothing. The `proptest!` macro passes the attribute through and the matrix shows both proptest fns bound.
- **Dependencies.** The spelling is the same in both manifests. `=0.1.0` sits on a dev-dependency of `publish = false` crates, so it does not reach consumers, and the CLAUDE.md rule against exact-pinning shared crates is about normal dependencies of library crates. The proc-macro has no dependencies of its own. `make size` builds the footprint without dev-dependencies, and its graph check looks only for the four shared exact crates. The lock adds one package from one source, and `scripts/check_one_copy.awk` passes. `cargo deny --workspace check licenses bans sources` exits 0 at both base and head with identical warnings, so the `wildcard` warnings are pre-existing. They come from the git dependencies with no `version` and the footprint's path dependency, and the new entry, which has a version, adds none. No weakening: `unknown-git = "deny"` stays, and the new entry is scoped to one repository.
- **The 7 lines left unconverted** are correct to leave. They sit on enums and the `exact` module, next to `compile_fail` doctests. A trace id on a container binds nothing either way. Measured in a throwaway worktree: replacing the `src/exact/ieee.rs` doc line with `#[trace(...)]` on `IeeeDisposition` or on `negotiate_ieee` binds nothing, and it also makes the current `[tag-on-non-binding-symbol]` warning disappear (quire records only a `mention` citation), so converting would hide a known gap. `#[implements(...)]` on those production items records only a `mention` citation (no claim, coverage unchanged at 86/185). On a test fn it gives an `evidence_near_miss` citation and backs nothing. It would also need `ix-trace-rs` as a normal dependency of a `no_std` crate. The criteria involved (NFR-002-AC-3, interface-001-AC-2, interface-001-AC-4, FR-009-AC-5) are unbacked at both base and head. That is a pre-existing gap for a separate ticket, not part of this PR.

Gates run at 559313a in a throwaway worktree with its own target directory, under `flock /tmp/luna-ir-heavy.lock`, with `CARGO_BUILD_JOBS=2`: `cargo fmt --all -- --check` clean. `make lint`, both lines: `cargo clippy --locked -p quire-contract-runtime --all-targets --all-features -- -D warnings` clean, and `cargo clippy --locked -p quire-contract-runtime-footprint --lib --release --target thumbv7em-none-eabi -- -D warnings` clean. `make test` (`cargo test --locked --all-features`): every binary is `ok`, with no failures and no warnings. `make test-features` (`scripts/run_feature_matrix.py`): `verified 14 feature sets`. These include `test-core` and `test-alloc` (`--no-default-features` and `alloc`, where the `snapshot-json` `mod json` and its import are compiled out); `test-snapshot-json` (`--no-default-features --features snapshot-json`, where they are compiled in); `test-footprint`, which compiles `population_tests` against the footprint dev-dependency; `test-exact`; and the two `thumbv7em-none-eabi` `no_std` MSRV builds. `make doc`, both lines, is clean with `-Dwarnings`. `make msrv` (`rustup run 1.98.1 cargo check --locked --all-targets --all-features`) is clean. As an extra check, `cargo clippy --locked -p quire-contract-runtime --all-targets --no-default-features -- -D warnings` is also clean, so no import is left unused when the features are off. `cargo deny --workspace check licenses bans sources` passes at base and at head, with the same warnings. Kani was not run: the PR changes no proof or production code, and `verification/kani.rs` is untouched.
